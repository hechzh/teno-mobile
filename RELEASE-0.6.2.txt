定位与修改
1. 计时停在 0：JwdService 仅在设备事件发生时发布 elapsed_ms，Flutter 每 500ms 读取的仍是同一份缓存。现在每次设备事件保存单调时钟锚点，NativeRuntime 按当前单调时钟计算经过时长。暂停冻结、继续扣除暂停时长，后台恢复补齐，断连冻结最后已知时长并保留 interrupted，重连按设备回报重新对时。没有伪造设备确认或自动停止设备。
2. 设备识别：HQ-10_P 已在厂商名称候选中，旧 Flutter 扫描页却直接显示全部蓝牙结果。本轮进入未连接的设备页自动搜索，按已核实服务、已保存密钥、广播服务、厂商名称排序；其他设备可展开。名称只是候选，首次连接仍先核实实际服务再进入已有密钥确认。已保存密钥直接复用，实际 GATT 连接仍核实服务和通道。
3. 新设备一次点击后，服务核实成功继续进入密钥确认；取消、离开页面、权限失败或核实失败不会创建密钥或启动录音。未绑定设备仍由用户明确选择新密钥，不自动重置已有设备。
4. 实时转写链路此前已存在：录音卡 Opus → 厂商解码 → PCM → 已有实时 WebSocket。原生桥没有单独传递实时状态，设备提示覆盖了转写提示，解码错误也未显示。现在通过独立 previewStatus 显示等待音频、连接/忙碌、暂停和解码失败；折叠预览移到内容开头，默认无需展开即可看见状态，展开可看文字。
5. 实时预览开关保留；关闭时明确提示 Settings > Recorder。预览失败不会停止设备录音，也不会绕过完整文件的长度、CRC 和解码校验。最终转写和摘要仍在完整文件保存并上传后处理。

验证与证据
以 verification/v0.6.2 下实际报告和 dist/Teno-0.6.2-release-manifest.json 的计数、APK SHA256 为准。
- Flutter 分析与 302 项完整功能及界面回归通过；额外覆盖自动搜索、候选折叠、已保存密钥、新设备核实后继续、离开/失败取消、权限失败和预览异常的大小字号布局。Release lint 为 0 错误、69 条警告。
- 最终原签名 APK 的独立原生回归 65 项、覆盖更新与冷启动通过。没有卸载或清除测试资料；检查对应最终 APK SHA256。
- 原生覆盖升级 71 项：在原 0.6.1 中种入合成账号、加密密钥、音频/文档及队列，然后同签名覆盖，未卸载。最初以 x86 进程运行时厂商 ARM-only 库无法加载，失败证据保留；选择 ARM64 转译后完整检查通过。升级候选包 SHA 与最终包的独立回归 SHA 分别记录。
- 原生 JWD 检查使用合成 BLE 回报、80 字节合成 Opus 帧、厂商 ARM 解码库及本机回环 WebSocket。验证无后续 BLE 事件时计时前进、暂停/继续/后台/断连/重连；碎片音频全部解码并发送 PCM，返回的固定测试文字进入 Flutter bridge，解码错误和服务忙碌可见。
- 上述 WebSocket 返回固定合成文字，不是 Azure 语音准确率测试。真实设备蓝牙、手机麦克风质量和厂商后台仍未验收。
- 本轮后端 1.4.1 未修改、未部署；12 项新 HTTPS 只读/临时会话检查通过。没有创建生产实时会话或发起 Azure / DeepSeek 调用。
- 87 个独立界面状态 × 浅色、深色、360dp/1.5 字号，261 张 Flutter 截图；系统选择器、键盘及冷启动为另存的原生模拟器截图。图册说明参考分类与推定，功能测试和视觉验收分开。
