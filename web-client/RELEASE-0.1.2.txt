Recording read cache
Previously every recording entry fetched all text again and requested a freshly
computed waveform. Revisited recordings now display an account-scoped saved
snapshot while checking the current server content. Unchanged recording revisions
reuse saved waveform peaks; opening a recording never runs transcription again.

Recordings, each transcript variant, notes, metadata, processing state and waveform
peaks are cached in memory and separate IndexedDB storage. The limit is 24 recent
recording/variant entries, 8 MiB and seven days. Credentials and audio are excluded.
Logout, cache clearing, mutations (including ambiguous failures), inaccessible
recordings and cross-tab invalidation clear read data. Retained imports are separate.
Stale requests from an old account cannot populate the next account's cache.

A saved copy is labelled while checking or offline. Server results replace it
without a blank loading screen. Cache storage failure leaves cloud reads usable.
First visits still require network and initial waveform computation; this does not
add offline sign-in, an offline library, or background browser uploads.
