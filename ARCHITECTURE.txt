Teno0.6.0 Android personal core — current

Android host app/ keeps recording, JWD SDK, encryption, durable upload queue,
URI staging/permissions, camera, calendar, audio playback/export and App lock.
shared-ui/lib/features/personal_* contains the current Android presentation.
The Pigeon platformCommand bridge exposes structured results, never private file
paths or provider keys. Themes and personal preferences are cached per account.

Shared backend1.4.0 adds migration007 without rewriting old business records.
The personal pipeline is explicitly selected on uploads and manual reprocessing;
old clients retain their original behavior. Files, notes/revisions, variants,
speaker names, recording metadata and share snapshots have separate owner-scoped
tables. Word/PPTX rendering and OCR run locally on the server. New personal jobs
and prompts remain independent of team meeting/profile/task generation.

Personal exports and public links resolve current ownership and source availability.
The latter copy a fixed content version and default to no audio, summary only,
seven days. Deleting/trashing the source or revoking/expiring the link invalidates it.

UI evidence: design-baseline/v0.6.0, one independent page/state per canvas and
three display variants. Runtime evidence: verification/v0.6.0 only. Historical
0.5.0/iOS/hardware results are not inherited. Physical Magic4 Pro/JWD and a paid
near-120-minute provider call remain unverified. The split/time-axis boundary is

Teno mobile architecture — approved 2026-11-04

Design: the 33 individual pages in design-review/plaud-rebuild/20261104.
Product text is Teno / Ask Teno, in English. The reference contains official
4.0-series screenshots and inferred states; it is not an Android runtime capture.
Current scope: authentication, device/phone recording, imports, local retention,
upload/processing, library/folders/search, playback, transcript editing, summaries,
templates, Ask, settings, export and trash. Work, Tasks, Routines, Skills,
Connectors, photos, independent notes and public share links have no mobile entry.

One repository, three components:
  app/          Existing Android host and Java runtime. Same package and signing.
  shared-ui/    Flutter module: presentation, view models, API repositories.
  ios/          Swift host, native runtime, and the supplied Objective-C JWD SDK.
The generated .android/.ios Flutter wrappers are never maintained or committed.

Pigeon defines the host API and typed runtime notifications. Native runtimes own
capture, file persistence, Bluetooth, decoder, authenticated HTTP, WebSocket,
token refresh, playback and durable uploads. No raw audio crosses Dart channels.
The UI reconstructs state from a snapshot after attach; events are UI updates,
not the durable source of truth. Platform services do not depend on a Flutter UI.

Server contracts stay at /api/v1. The existing web and backend are not modified.
Each platform owns one serialized session refresh. No Azure/DeepSeek credentials
are client configuration. Recognition always uses auto; live text is only preview.
Complete recordings still go through post-record processing on the server.

Android compatibility: SharedPreferences teno; AndroidKeyStore teno.session;
drafts/<scope>; original encrypted device keys, recorder identity, sync ledger,
recording options, file paths and client_id are retained. Existing team data is
left in place without starting any team sharing or exposing team management.
An in-place update, not an uninstall, is required for migration verification.

iOS: CoreBluetooth owns scanning/connection/restoration. The supplied JWDClient
receives discovered peripherals and confirmation callbacks. Keychain stores
session/device secrets. Imported media is copied into private Application Support.
Device keys from an existing binding must be imported; no automatic reset/rebind.

Recording: connect -> confirmed start/pause/resume/stop -> download -> length and
OFF completion -> available CRC match -> strict decode -> durable local draft ->
durable upload -> processing -> result. Disconnection never proves stopped state.
Preview concealment cannot qualify a damaged final file for upload. Retries keep
the original client_id. Account changes cannot reassign another account's draft.

Delivery: public hechzh/teno-mobile, necessary vendor dependencies authorized by
the user. API keys, signing keys, accounts, AGENTS, recordings and logs excluded.
Android signed builds use the existing local keystore. GitHub macOS builds an
unsigned iOS IPA; AltStore Classic signs locally with the user's Apple account.
Free provisioning expires after about seven days. No automatic store submission.

Evidence: distinguish compile/unit/simulator tests from actual iPhone, Magic4 Pro
and JWD tests. A mock transport is allowed only in test targets. Production has
no synthetic devices, fake battery values, fake transcripts or demo account.

Implementation map (0.5.0)

shared-ui/lib/main.dart mounts an account-scoped navigator. core/model.dart owns
the current RuntimeState, library repository, scoped requests and processing poll.
features/home/library/recorder/detail/ask/settings/login own their page-local forms
and request lifetimes. ui/widgets.dart supplies the common tokens and controls.
No platform-specific API token is exposed to these classes.

pigeons/runtime.dart is the only channel schema. RuntimeHost commands return
explicit results/errors; RuntimeEvents.changed carries an ordered snapshot of
SessionState, CaptureState, DeviceState, PlaybackState and account-local drafts.
Old sequence numbers are ignored. Native file paths and keys do not appear in
snapshots. Hardware acknowledgements, not a successful channel invocation, change
recording state. Every platform regenerates its bridge from the same pinned schema.

Android MainActivity is the existing notification/deep-link entry and now owns a
Flutter engine attachment. NativeRuntime adapts Store/Api, RecorderService,
JwdService, UploadQueue and NativeMedia. RecorderService remains a foreground
service with its microphone notification; Flutter disposal only detaches observers.
Upload jobs and sync receipts retain their pre-0.5 storage representation. Legacy
team activities are not compiled into the new APK; retained source/history does not
create a navigation entry. The old account, key and draft data are never rewritten
as a prerequisite to opening the new interface.

iOS AppDelegate owns the Flutter engine and NativeRuntime. NativeBridge maps native
failures into typed errors without stack traces. NativeStore owns protected JSON
and Keychain; SessionTransport owns authenticated requests and the one refresh task.
PhoneRecorder writes PCMFile through an AVAudioEngine tap. JwdRecorder is the
CoreBluetooth owner and delegates wire parsing to JwdVtrSDK, with StrictAudio for
final-file CRC and decoding. UploadQueue uses a background URLSession with a
persistent per-file receipt. NativeMedia owns picker, player and share presentation.
Bluetooth is initialized only after a recorder action, or to restore prior usage.

Queue state and recovery

recording -> local -> queued -> uploading -> processing -> ready
                       ^           |
                       +-- retry --+
invalid files never enter queued; manual retry retains the original identity.
Draft JSON is committed before requesting an upload. Successful server receipts
store recording_id/job_id; the original audio remains. After abrupt phone-process
termination, WAV headers are repaired from committed even-byte PCM and marked for
review. Recovered audio is not treated as an uninterrupted recording.

Android serializes account changes with native work; cancellation disconnects an
active upload and waits for the worker to quiesce before replacing credentials.
iOS pauses scheduling, increments a generation fence, cancels OS upload tasks and
keeps their original account receipts. Async completion verifies its owner/generation
before writing. Both platforms clear the old UI route stack, player and preview.
Returning to the same account resumes its own queue. A new account cannot adopt it.

For device capture, pending start/pause/resume/stop remains visible until confirmed.
Disconnect during capture produces interrupted, including unknown-running state.
Reconnection queries the actual recorder; it does not issue an automatic reset or
claim the old session stopped. Verified transfer/decode creates a local draft only
after completion. Preview packet loss never weakens final-file verification.

Build and release boundaries

Android min/compile/target API: 26/36/35. Java 21, Gradle 9.1.0, AGP 9.0.1 and
Kotlin 2.2.20 are pinned for Flutter 3.47.9 add-to-app integration. iOS minimum 15,
Xcode 16.4 / XcodeGen 2.46.0, Swift 5. The generated Swift package and Xcode project
are rebuilt by CI; ios/project.yml is the source of host configuration.
The Linux job verifies generated bridges, analysis, tests and Android lint/build.
The macOS job tests the native host and launches it for a simulator screenshot.
OCR must confirm the Teno / Sign in screen before the job builds a Release device
app and unsigned IPA. App Store distribution is a separate
future signing/review configuration, not a consequence of these internal builds.
